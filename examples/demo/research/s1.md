# How does SQLite run behind a small web app?

**Short answer:** SQLite is a library, not a server. The web app opens the database file directly, and that is enough for a family-sized app.

## What to use

- One database file next to the app, opened by the app process.
- WAL mode, so readers do not wait for a writer.
- A backup that copies the file while the app runs (`VACUUM INTO` or the backup API).

## How to set it up

1. Open the file once when the app starts.
2. Run `PRAGMA journal_mode = WAL;` on that connection.
3. Keep writes short: one transaction per save.

```sql
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;
```

## Limits to know

| Limit | What it means here |
|---|---|
| One writer at a time | Fine: a family saves a recipe a few times a day. |
| File on a network drive | Avoid it; keep the file on the app's own disk. |

> SQLite works well as the database engine for most low to medium traffic websites.
